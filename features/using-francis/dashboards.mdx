In Francis, you build dashboards on top of your financial model. Every table, chart, and metric box pulls live data from the model and updates automatically, so once the model holds clean data, your reporting follows without a separate rebuild.

This keeps reporting downstream of the model. Fix a number once, in the model, and every dashboard that references it updates.

## Dashboard primitives

A dashboard is built from primitives. You can add:

- **Heading**: titles in your dashboard, as H1, H2, or H3.
- **Text**: commentary, with standard formatting including bold, italic, numbered lists, and bullets.
- **Table**: summaries, variance analysis, or side-by-side comparisons. See [tables](/features/using-francis/tables/overview).
- **Chart**: a visual highlight of key metrics. See [charts](/features/using-francis/charts/overview).
- **Metric**: a box highlighting a single number, with an optional comparison against another version or period. See [metric box](/features/using-francis/metric-box).
- **Image**: logos, brand imagery, or screenshots of analysis you can't build in the dashboard. Use it to bring any external analysis into one place alongside your live data.
- **Spacer**: white space. Useful for a less dense layout, or to fill space before a page break.

Right-click a primitive to duplicate, copy, or delete it. You can also delete one by selecting it and pressing **Backspace**.

## Auto layout

Drag and drop any primitive to position it wherever you want in the dashboard. Dashboards use auto layout, so moving or adding one can push others around to keep everything aligned. This sometimes shifts a primitive onto the next page in pursuit of a clean layout.

You control the vertical length of charts, images, and spacers. Headings, text boxes, and tables size themselves to their content, so their length isn't adjustable.

Every primitive fills the full horizontal width by default, and you can't set a width directly. To place primitives side by side, drag one next to another. Once two or more sit on the same row, you can adjust their relative widths so one takes more space than the others.

## Date settings and the Last Close month

Set the **Last Close** month in the top bar. This setting syncs with your model. Several date ranges used in tables, metric boxes and charts (Last month, YTD, LTM, Full year, Last year, and Next year) update dynamically from it, and actuals in charts and tables display through the Last Close month. For a fixed range instead, choose **Custom dates**.

To update the dashboard to a new month's close, update the Last Close month and all tables, charts and metric boxes that reference dynamic ranges update automatically.

## Sharing and exporting dashboards

You can share a dashboard three ways:

1. **Workspace access**: owners, admins, editors, and viewers reach dashboards the same way they reach sheets in the model.
2. **Limited Viewer access**: invite specific people into a specific dashboard as Limited Viewers.
3. **PDF export**: download the dashboard as a PDF.

Inviting people into a dashboard means no space restrictions. Tables can be as wide and as long as you need.

A PDF is fixed and opens easily across devices, but it introduces space restrictions on primitive width and length. Before exporting, make sure no primitive breaks across a page or runs too wide. Where one does, add a spacer to push it onto the next page.

A spacer only helps a primitive that fits on a page but straddles a break. A table taller than a page can't be pushed anywhere useful, and no primitive splits across pages. Fix that one in the model instead: a table shows one section, so split the section in two and place a table for each. If you don't want to restructure the model you forecast in, build a separate reporting sheet whose sections hold [calculations](/features/using-francis/components) referencing the rows you want, sized so each section fits a page.

### Canvas and Print Preview

Dashboards have two view modes to guide this work:

- **Canvas**: one continuous canvas with no page breaks. Use it for dashboards you invite people into.
- **Print Preview**: shows page breaks and flags any space-restriction violations with red lines. Use it when you plan to export to PDF.

## FAQ

<AccordionGroup>
  <Accordion title="Can I show just some groups in a dashboard, not an entire section?" id="faq-partial-section">
    No. A dashboard shows a whole section, not a subset of it, and rows with no activity can't be hidden either. To present a narrower view, build a separate section in the model with [calculations](/features/using-francis/components) that reference exactly the groups and rows you want, and share that section instead.
  </Accordion>
  <Accordion title="My table is longer than one page. Can it print across two?" id="faq-table-across-pages">
    No. No primitive splits across pages in a PDF, and a table sizes itself to its content, so a table taller than a page can't be made to fit or continue overleaf. A spacer won't help either, since it can only move a primitive that already fits.

    Split it in the model. A table shows one section, so divide that section into two and put a table for each on its own page. To leave your forecast model untouched, build a separate reporting sheet whose sections hold calculations referencing the rows you want, each section sized to fit a page. Use Print Preview to check where the breaks land.

    Sharing the dashboard rather than exporting it removes the constraint entirely. Tables can be as long as you need for people you invite in as Limited Viewers.
  </Accordion>
</AccordionGroup>
